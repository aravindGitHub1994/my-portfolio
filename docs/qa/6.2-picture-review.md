## 0 · How to look at them

No server needed. The shipped copies are in `public/pictures/`:

- `<id>.jpg` — the viewer copy, bounded to 1200×900
- `<id>-thumb.jpg` — the 192×144 grid thumbnail

Open the folder in Explorer at Large Icons and you have the grid the Gallery
will show. `scripts/pictures-manifest.tsv` lists every id, group and shipped
size.

That is headroom, not a fault — but it does reopen exactly one number 6.1 asked

29 photographs at 4.31 MB.** At 23 photographs the same setting spends 3.39 MB,

the band and every remaining photograph would look slightly better.
**Not changed** — it re-encodes all 23 files and it is a taste call, not a defect.

#### Answered: always, playful, and the drafts are in §2.

You took option 2 and then set the register: **playful and witty, Instagram-ish,
for the 23 keepers.** §2's caption column is written that way. **Every line is
mine, not yours** — the point of a draft in your voice is that you overwrite the
half that isn't.

Two rules I kept even with the register loosened, because they are what separate
a joke from a fabrication:

- **A caption may only joke about what is visible in its own photograph.** No
  dates, no place I could not read off the id, nobody's name, no weather I could
  not see, no invented durations ("for four minutes", "for six hours") and no
  claim about what anyone was feeling. The wit comes from framing what is there,
  not from adding events.
- **Nothing is asserted about the other people in frame.** `guitar-01` has two
  identifiable faces in it; the caption jokes about the *guitar*, not about them.

**`⚑` marks the four lines that still assert something I could not verify** —
`cat-07` (that the scene's cat tree is this one), `hike-01` (that the dog was
with you), `ride-07` (that this was a ride *to* Pondicherry), `guitar-01` (that
the three of you were together). Those four are the ones to check rather than
just enjoy.

**One factual claim, deliberately:** `ride-12`'s "953 windows" is the published
figure for Hawa Mahal's jharokhas, not something about you. Strike it if you'd
rather not put a number on the internet.

**Structural consequence for 6.4:** captions always render, so every id needs a
non-empty string. Where a draft is struck and not replaced, 6.4 falls back to
the place name from the id — no blank status bar, no padding.

## 3 · What 6.1 guarantees, so you do not have to check it

Recorded so this gate stays about the photographs rather than the pipeline:

- **The allow-list is explicit and never globs a directory.** The 29 entries
  are typed out in `scripts/build-pictures.mjs`. A file dropped into
  `assets-src/` cannot ship by accident.
- **The script refuses to run** if any entry's path matches tattoo reference
  material, the AI concept sheets, the character-QA screenshots,
  `docs/projects/**` or anything named "client". Proved by poisoning the list
  with `tattoo01.jpg` — it exits 1 and writes nothing.
- **No AI concept sheets and no client material ship.** Neither is in the list.
- **All metadata is stripped** — measured: 0 of 29 shipped files carry EXIF,
  XMP or ICC. (Worth knowing: 0 of 29 *sources* carried EXIF either, so no GPS
  was ever at risk here. The stripping is still correct, and matters the moment
  a photograph is added straight off a phone.)
- **Re-running is idempotent** — byte-identical output, `git status` clean.
- **`assets-src/` is now gitignored, not merely untracked.** It was one
  `git add -A` away from committing 27 MB including the tattoo references.
- **No new build step.** `npm run build` is still a plain static export; the
  images are committed. `npm run pictures` is run by hand when the set changes.
